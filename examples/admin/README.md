# Admin panel example

The back office of a small shop, generated by `renox-admin` from three
models: products, categories and customers. No page is written by hand;
each model is declared once in `src/resources/` (its grid columns, its form
fields, its filters and actions) and its `Policy` says who may do what.

```text
cp .env.example .env    # optional: the settings this example reads
cargo run -- migrate
cargo run -- db:seed    # admin@example.com and editor@example.com / password123
cargo run               # http://127.0.0.1:3000 (it opens the panel at /admin)
```

Log in as `admin@example.com` to do everything, or as `editor@example.com`
to see what an editor may: add and change products and categories, look at
customers, delete nothing.

## What to try

- **The list.** Products: type in the search box (name or SKU), filter a
  heading (Status, Price, Released), sort, or pick a tab: Live, Low stock,
  Featured. The Stock column is the app's own cell
  (`resources/views/renox-admin/products/cells.html`), with a badge when it
  runs low. The category comes from its own table (`Column::related`).
- **Add and edit.** New product: leave the name empty or reuse a SKU (try
  `COF-ARB`) and save: the errors show under the fields and nothing is lost.
  The category is a searchable select of the categories table
  (`Field::belongs_to`). Saving goes back to the list with a toast.
- **Actions.** Tick rows and Publish or Feature them, or "Select all
  matching" for every row the filters match. Publish is also in each row's
  ⋯ menu (`AdminAction::row`).
- **Delete and the trash.** As the admin, delete a product (from its row,
  its page, or a selection): it goes to the Trash tab, where Restore brings
  it back and "Delete for good" removes it. Products have soft deletes;
  categories and customers don't, so their deletes can't be undone.
- **Export.** The download button over each list: CSV, a print page, and
  Excel when built with `--features renox/xlsx`. The export holds the rows
  the filters, the search and the tab match.
- **Roles.** As the editor: no Delete anywhere, no Trash tab, and customers
  are read-only (their policy asks for `customers.manage`). The panel itself
  is open to users with a role (`Admin::authorize` in `src/lib.rs`); anyone
  else gets 403.

## Where things are

| Part | Files |
|---|---|
| The panel, roles | `src/lib.rs` (`panel()`, `ROLES`) |
| Products: columns, fields, filters, actions, unique SKU | `src/resources/products.rs` |
| Categories: no view page, a product count | `src/resources/categories.rs` |
| Customers: read-only for editors | `src/resources/customers.rs` |
| The Stock cells | `resources/views/renox-admin/products/cells.html` |
| Seed data | `src/seed.rs` |
| Tests | `tests/admin.rs` |

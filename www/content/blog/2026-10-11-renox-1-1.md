Renox 1.1 is out. Update with `renox = "1.1"`, or install the CLI:

```bash
cargo install renox-cli
rnx new shop && cd shop
rnx serve
```

It is additive: `cargo semver-checks` against 1.0.0 finds nothing breaking, and 1.0 apps keep compiling. Two things can touch an existing app, and both are in the [changelog](https://docs.renox.rs/docs/changelog): templates that already used `rx-` or `app-` tag names for their own markup need renaming, and the new device tokens come with one framework migration, so run `migrate` after upgrading.

## Pages are HTML tags

The UI kit is now written as tags. A page looks like HTML:

```html
<rx-page layout="layouts/app.html" title="Orders">
  <rx-table :rows="orders" caption="Orders">
    <rx-column label="Number">{{ row.number }}</rx-column>
    <rx-column label="Total" align="num">{{ row.total | money }}</rx-column>
    <rx-slot name="empty"><rx-empty title="No orders yet"/></rx-slot>
  </rx-table>
</rx-page>
```

- **No build step.** The tags are compiled to MiniJinja when a template loads, so live reload, overriding built-in views and `embedded!()` all keep working. A template without tags is left exactly as it was.
- **Mistakes name their place.** A wrong tag or attribute fails with the file, the line and a "did you mean". `rnx view:check` loads every template and checks components and route names; `TestApp::assert_views_compile` does the same in a test.
- **Your own tags.** `components/price_tag.html` is `<app-price-tag>`, with its props declared in the file. Plugins register theirs.
- **Editor autocomplete.** `rnx view:data` writes the tag list that VS Code and other editors read.

The macros underneath stay supported. `rnx new`, the starter kit, the examples and the guides use tags. The guide is [Components as tags](https://docs.renox.rs/docs/ui).

## Live components

Some parts of a page have several states and several actions. A live component keeps that state in a Rust struct: a button calls a method, the server changes the state and renders the component again, and the browser morphs the page into it. There is no route, no fragment and no JavaScript to write.

```rust
#[renox::live_component(view = "live/counter.html")]
impl Counter {
    #[live(action)]
    async fn add(&mut self, _ctx: &mut LiveContext, n: i64) -> Result {
        self.count += n;
        Ok(())
    }
}
```

In the template, `rx-click="add(1)"` calls the method, `rx-model` binds a field, and `<live-counter :component="counter"/>` mounts it. The state travels signed, and `LIVE_SNAPSHOT_MAX_SIZE` caps its size. htmx and Alpine stay the base of the framework; a live component is the tool for a part with state. The bike shop shows both on the same checklist, at [/about/htmx](https://bikeshop.renox.rs/about/htmx) and [/about/htmx/live](https://bikeshop.renox.rs/about/htmx/live). See [the guide](https://docs.renox.rs/docs/live).

## Checks before the browser

- **`rnx db:check`** compares every model registered with `App::model` with its table and fails on a mismatch. `TestApp::assert_models_match_schema` does it in a test.
- **`rnx make:migration --auto`** writes the difference between your models and your migrations as plain SQL to review, for SQLite and PostgreSQL. Fields can carry `index`, `unique`, `default` and `references`.
- **Typed columns.** `Product::query().where_(Product::PRICE.lt(20_000))` instead of a string column name.
- **`#[model(form)]`** makes the model's form struct, so a new field is added in one place.
- **`rnx doctor`** says what this machine or app is missing.

## And the gaps the bike shop found

Building [the bike shop](/blog/meet-the-bike-shop) showed what Renox lacked. The 1.1 additions that came from it:

- device tokens for kiosks and tills (`auth::DeviceToken` and the `Device` extractor);
- grid columns computed in SQL, and several sheets in one Excel file (`grid::Workbook`);
- a heatmap chart;
- seeders from modules, and `permissions::users_with_permission`;
- renox-admin actions that ask for input, relation managers and layout slots; renox-billing named guards and paused subscriptions.

The [changelog](https://docs.renox.rs/docs/changelog) lists everything.
